When a shared read (`get_context_snapshot` or `pickup_work(consume="false")`, CLI `dct pickup --consume never`) refuses with SchemaNotReady, explain that setup or a schema upgrade is required. Propose `dct db upgrade` with explicit consent, then retry the original read only after that migration succeeds. Never invoke an unrelated writer to trigger a hidden migration. A SQLite reader may create WAL/SHM sidecars; it does not initialize the database, change journal mode, schema or data. Do not infer this guarantee for other list/get tools.
